A composable application sidebar, ported from shadcn/ui and built on Base UI primitives. It collapses off canvas or down to icons on desktop, becomes a `Sheet` on small screens, remembers its state in a cookie, and toggles with <kbd>⌘ B</kbd> / <kbd>Ctrl B</kbd>.

<Example padding="4">
  <SidebarExample />

  ```jsx
  <SidebarProvider>
    <Sidebar collapsible="icon">
      <SidebarHeader>
        <SidebarMenu>
          <SidebarMenuItem>
            <SidebarMenuButton size="lg" tooltip="Acme Inc">
              <Globe />
              <span>Acme Inc</span>
            </SidebarMenuButton>
          </SidebarMenuItem>
        </SidebarMenu>
      </SidebarHeader>
      <SidebarContent>
        <SidebarGroup>
          <SidebarGroupLabel>Platform</SidebarGroupLabel>
          <SidebarGroupContent>
            <SidebarMenu>
              <SidebarMenuItem>
                <SidebarMenuButton isActive tooltip="Home" render={<a href="/" />}>
                  <Home />
                  <span>Home</span>
                </SidebarMenuButton>
              </SidebarMenuItem>
              <SidebarMenuItem>
                <SidebarMenuButton tooltip="Inbox" render={<a href="/inbox" />}>
                  <Inbox />
                  <span>Inbox</span>
                </SidebarMenuButton>
                <SidebarMenuBadge>12</SidebarMenuBadge>
              </SidebarMenuItem>
            </SidebarMenu>
          </SidebarGroupContent>
        </SidebarGroup>
      </SidebarContent>
      <SidebarFooter>{/* user menu */}</SidebarFooter>
      <SidebarRail />
    </Sidebar>
    <SidebarInset>
      <header>
        <SidebarTrigger />
      </header>
      {children}
    </SidebarInset>
  </SidebarProvider>
  ```
</Example>

## Structure

A sidebar is assembled from the following parts:

- `SidebarProvider` holds the open state and wraps both the sidebar and the page content.
- `Sidebar` is the sidebar container.
- `SidebarHeader` and `SidebarFooter` stick to the top and bottom.
- `SidebarContent` is the scrollable middle section.
- `SidebarGroup` is a section within `SidebarContent`, with an optional `SidebarGroupLabel` and `SidebarGroupAction`.
- `SidebarMenu`, `SidebarMenuItem` and `SidebarMenuButton` render the navigation items.
- `SidebarTrigger` and `SidebarRail` toggle the sidebar.
- `SidebarInset` is the main content area next to the sidebar.

In an application, `SidebarProvider` usually wraps the whole layout. It fills at least the viewport height and the desktop sidebar is `fixed` to the viewport edge. The demos on this page put the provider inside a bordered frame and pass `className="absolute h-full"` to `Sidebar` so that it stays inside the frame.

## Variants, collapsing and side

`variant` sets the visual style: `sidebar` (attached, with a border), `floating` (a card with a border and shadow) or `inset` (the main content is lifted into a card next to the sidebar). For `inset`, put your page inside `SidebarInset`.

`collapsible` controls how the sidebar closes on desktop: `offcanvas` slides it out of view, `icon` shrinks it to a strip of icons, and `none` keeps it open. `side` places it on the `left` or `right`.

<Example padding="4">
  <SidebarVariantsExample />

  ```jsx
  <SidebarProvider>
    <Sidebar variant="inset" collapsible="icon" side="left">
      {/* ... */}
    </Sidebar>
    <SidebarInset>{children}</SidebarInset>
  </SidebarProvider>
  ```
</Example>

## Controlled

Pass `open` and `onOpenChange` to `SidebarProvider` to control the desktop open state. On small screens the sidebar opens as a sheet with its own state, `openMobile`, which `useSidebar` exposes.

<Example padding="4">
  <SidebarControlledExample />

  ```jsx
  const [open, setOpen] = useState(true);

  <SidebarProvider open={open} onOpenChange={setOpen}>
    <Sidebar>{/* ... */}</Sidebar>
    <SidebarInset>{children}</SidebarInset>
  </SidebarProvider>
  ```
</Example>

### Persisting state

Each change writes the open state to a `sidebar_state` cookie for seven days. Read the cookie on the server and pass it as `defaultOpen` so the first render matches the user's last choice:

```jsx
const cookieStore = await cookies();
const defaultOpen = cookieStore.get('sidebar_state')?.value !== 'false';

<SidebarProvider defaultOpen={defaultOpen}>{children}</SidebarProvider>
```

## Menu buttons

`SidebarMenuButton` renders a `button` by default. Use `render` to turn it into a link or a router link, and `isActive` to mark the current page. When the sidebar is collapsed to icons, a `tooltip` shows the label next to the icon.

```jsx
<SidebarMenuButton isActive tooltip="Home" render={<a href="/" />}>
  <Home />
  <span>Home</span>
</SidebarMenuButton>
```

Add a `SidebarMenuAction` beside a button for a secondary action, and a `SidebarMenuBadge` for a count. With `showOnHover`, the action only appears while the item is hovered or focused.

```jsx
<SidebarMenuItem>
  <SidebarMenuButton render={<a href="/projects/docs" />}>
    <Folder />
    <span>Docs</span>
  </SidebarMenuButton>
  <SidebarMenuAction showOnHover>
    <MoreHorizontal />
    <span className="sr-only">More</span>
  </SidebarMenuAction>
</SidebarMenuItem>
```

## Submenus

Nest a `SidebarMenuSub` in a menu item for a second level. Combine it with `Collapsible` to make the group expandable. The trigger renders the menu button and the chevron rotates with `group-data-panel-open/menu-button:rotate-90`.

```jsx
<Collapsible defaultExpanded render={<SidebarMenuItem />}>
  <CollapsibleTrigger render={<SidebarMenuButton tooltip="Settings" />}>
    <Settings2 />
    <span>Settings</span>
    <ChevronRight className="ml-auto transition-transform group-data-panel-open/menu-button:rotate-90" />
  </CollapsibleTrigger>
  <CollapsiblePanel>
    <SidebarMenuSub>
      <SidebarMenuSubItem>
        <SidebarMenuSubButton href="/settings/general">General</SidebarMenuSubButton>
      </SidebarMenuSubItem>
    </SidebarMenuSub>
  </CollapsiblePanel>
</Collapsible>
```

## Loading

`SidebarMenuSkeleton` is a placeholder for menu items that are still loading.

## useSidebar

`useSidebar` reads the sidebar state from any component inside `SidebarProvider`, for example to build a custom trigger.

```jsx
const { state, open, setOpen, openMobile, setOpenMobile, isMobile, toggleSidebar } = useSidebar();
```

<PropertiesTable>
  <ResponseField name="state" type="'expanded' | 'collapsed'">The desktop state</ResponseField>
  <ResponseField name="open" type="boolean">Whether the desktop sidebar is open</ResponseField>
  <ResponseField name="setOpen" type="(open: boolean) => void">Opens or closes the desktop sidebar</ResponseField>
  <ResponseField name="openMobile" type="boolean">Whether the mobile sheet is open</ResponseField>
  <ResponseField name="setOpenMobile" type="(open: boolean) => void">Opens or closes the mobile sheet</ResponseField>
  <ResponseField name="isMobile" type="boolean">True below the `md` breakpoint (768px)</ResponseField>
  <ResponseField name="toggleSidebar" type="() => void">Toggles the desktop sidebar, or the mobile sheet on small screens</ResponseField>
</PropertiesTable>

## Theming

The sidebar uses the Zen theme tokens: `surface` for its background, `interactive` for hovered and active items, and `edge` for borders. Its widths come from CSS variables on `SidebarProvider`, which you can override with `style`:

```jsx
<SidebarProvider style={{ '--sidebar-width': '20rem', '--sidebar-width-icon': '3.5rem' }}>
```

The defaults are `16rem` expanded, `3rem` collapsed to icons, and `18rem` for the mobile sheet. Each part sets `data-slot` and `data-sidebar` attributes for styling, and the `Sidebar` root exposes `data-state`, `data-collapsible`, `data-variant` and `data-side`.

### SidebarProvider

<PropertiesTable>
  <ResponseField name="defaultOpen" type="boolean">Initial desktop open state when uncontrolled (default: true)</ResponseField>
  <ResponseField name="open" type="boolean">Controlled desktop open state. `isOpen` is accepted as an alias</ResponseField>
  <ResponseField name="onOpenChange" type="(open: boolean) => void">Called when the desktop open state changes</ResponseField>
  <ResponseField name="keyboardShortcut" type="string | false">Key that toggles the sidebar together with ⌘ or Ctrl. Pass `false` to disable it, for example when several providers share a page (default: "b")</ResponseField>
</PropertiesTable>

### Sidebar

<PropertiesTable>
  <ResponseField name="side" type="string">"left" | "right" (default: "left")</ResponseField>
  <ResponseField name="variant" type="string">"sidebar" | "floating" | "inset" (default: "sidebar")</ResponseField>
  <ResponseField name="collapsible" type="string">"offcanvas" | "icon" | "none" (default: "offcanvas")</ResponseField>
</PropertiesTable>

### SidebarMenuButton

<PropertiesTable>
